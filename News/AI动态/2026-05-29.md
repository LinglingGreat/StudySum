### Anthropic Engineering

**《近期 Claude Code 质量问题事后复盘》**

Anthropic 官方披露了导致 Claude Code 近期表现下降的三个独立问题，并逐一说明了根因与修复方案。

第一，3月4日将 Claude Code 默认推理强度从 high 降为 medium，目的是减少 Opus 4.6 在 high 模式下偶发的超长响应延迟。但这是错误的取舍——用户反馈更倾向于接受高延迟换取更高智能。该变更于4月7日回滚，目前 Opus 4.7 默认 xhigh、其余模型默认 high。

第二，3月26日上线了一项缓存优化，本意是会话闲置超1小时后清除旧的 thinking 记录。但实现存在 bug，导致此后每轮对话都会清除 thinking，使模型表现出健忘、重复、工具调用异常等症状，同时引发缓存未命中、token 消耗加速。该 bug 于4月10日修复。

第三，4月16日在系统提示中加入了限制输出长度的指令，配合其他改动后明显拉低了编程任务的质量，于4月20日回滚。

由于三个问题各自影响不同流量切片、发生时间错开，整体呈现出难以定位的广泛性退化。事后 Anthropic 为所有订阅用户重置用量限额，并承诺加强系统提示变更的评估流程与灰度控制。

https://www.anthropic.com/engineering/april-23-postmortem

**《Managed Agents 扩展：让"大脑"与"双手"解耦》**

Anthropic 工程博客深度拆解了 Managed Agents 的架构演进，核心思路是将 Claude 及其 harness（大脑）与沙盒/工具（双手）以及会话日志（session）彻底解耦。

早期架构将所有组件塞入单一容器，导致容器成为"宠物"——一旦失效整个会话就可能丢失；调试时工程师必须进入容器内部，但容器往往存有用户数据，无从操作。

解耦后，沙盒以工具调用方式 `execute(name, input) → string` 接入，容器挂掉只是一次工具调用失败，可以重新初始化；harness 本身也变成无状态，崩溃后用 `wake(sessionId)` 恢复即可。改造结果：p50 首 token 延迟下降约 60%，p95 下降超 90%。

安全层面，生成代码运行的沙盒与持有凭证的环境完全隔离，从根本上消除了凭证被提示注入窃取的风险。会话（session）作为独立于 Claude 上下文窗口之外的持久化日志，为超长任务提供了可查询、可回溯的上下文对象，而非依赖不可逆的 compaction 操作。

https://www.anthropic.com/engineering/managed-agents

### Claude Blog

**《Managed Agents 新功能：自托管沙盒与 MCP 隧道》**

Claude Managed Agents 开放两项新能力，让企业客户可以在自己的基础设施上运行 agent。

**自托管沙盒（公测）**：工具执行转移到你自己的环境——可选自建基础设施或 Cloudflare、Daytona、Modal、Vercel 等托管提供商。敏感文件、私有服务和代码不会离开你的安全边界，计算资源规格由你控制。Amplitude 正在用 Managed Agents + Cloudflare 构建内部设计 agent，Clay 用 Daytona 运行其 GTM 工程 agent，Rogo 则用 Vercel Sandbox 处理机构金融场景下的专有数据。

**MCP 隧道（研究预览）**：在不暴露公网端口的前提下，让 agent 访问内网私有 MCP server——内部数据库、私有 API、知识库都可以作为工具使用。网关只需建立一条出站连接，全程流量加密。

### AI & I by Every

**《我们用 AI 实现了全面自动化，员工却增加了三倍》**

**核心观点：自动化越多，专家需求越大**

Every CEO Dan Shipper 用自己公司的亲身经历，反驳了"AI 大规模消灭工作岗位"的主流叙事。Every 是一家深度使用 AI 的媒体公司——Claude Code、Codex、各类 agent 已渗透到每个工作流，如果在公司 Slack 里随机选一个人，命中 agent 的概率和命中真人差不多。但自 GPT-3 时代起，公司从 4 人扩张到了 30 人，仍在持续招聘。

他给出的解释框架简洁有力：**AI 让昨天的专家能力变得廉价**。任何人都可以用一个 prompt 写代码、做设计、出报告，于是大量"差不多正确但并不完全合适"的产出涌现出来。这些产出的价值被压低，但同时创造出大量需求——需要专家来将这些"堪用但不够好"的内容变成真正有价值的东西。他举了工程师的例子：COO Brandon 会把不确定能跑通的 PR 直接推过去，工程师 Willie 收到后往往会说"这个思路不错，但我把它完全重写了"。

> "Agent 离人越远，它的价值就越低。"

对于 ClickUp CEO 高调宣传裁员+AI 的做法，Shipper 直接批评为"格调低下"，并指出更可能的原因是公司本身表现不佳，而非 AI 替代了岗位。他援引 Codex 抓取 Reddit 的调研数据：大量客服裁员后的公司两个月内就回来重新招人，因为盲目上马 AI 根本跑不通；而且绝大多数拨打客服电话的用户，会明确要求"转人工"。

他的写作方法同样值得一提：每天早上把文章思路完整口述一遍录入文档，再让 Claude 反问"你到底想说什么"，逐步逼近核心论点。8000 字稿子写到 5000 字时，开始让 Codex 把最新草稿转成播客音频，通勤途中边走边听、边标注要改的地方。

最终结论：**只要跟上模型迭代节奏，你就不会被淘汰**。变革渗透的速度远比想象慢，而那些想过上有野心生活的人，AI 只会让这件事变得更可能实现。
