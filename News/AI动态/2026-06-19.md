### Aaron Levie（Box CEO）

Levie 发表了一篇对 Applied AI 层的深度判断。尽管早期有"应用层只是 LLM 上面的薄皮"的批评，他认为企业级 agentic 工作流的复杂性正在证明这一层具有真实的护城河。他总结出四个关键要素：

1. **构建连接智能与工作流的功能**：包括定制界面、专属工具，以及人机协同的 UX，远不止于呈现输出 token。
2. **成为模型路由器**：根据任务需求在前沿模型与经济型模型间灵活切换，业务模型对齐的平台天然具备这个优势。
3. **通过 FDE 驱动实施与变革管理**：数据清洗、流程重构、SLA 达成——每个领域都不同，深厚的领域经验是壁垒。
4. **以领域专属的 GTM 建立行业护城河**：能用客户的语言说话，懂行业的合规与监管，才能真正赢得企业信任。

他也坦承：或许未来模型能力能解决一切。但企业今天就需要帮助，而这些工作无论未来模型多强，都不会白做。

### Zara Zhang

对 AI 写作的一则清醒建议：在你形成自己的审美和写作风格之前，不要用 AI 来写作。如果 AI 产出的是平庸内容，你甚至识别不出来它是平庸的。她的建议：先大量阅读，弄清楚什么是好内容；再大量写作，找到自己的声音；之后再用 AI 辅助，但要确保输出的仍然是你自己的声音。

### AI & I by Every：《GitHub COO 解释为何 AI 还没有取代开发者》

**核心观点：** AI 时代的开发者角色没有消失，而是在扩张——不只是人数，更是"开发者"这个身份本身的边界。

GitHub COO Kyle Daigle 谈了 AI 对 GitHub 生态的真实影响。数据层面：2026 年 3 月，仅由 agent 提交的 PR 就达 1700 万个；按当前增速线性外推，今年全年 commit 量有望达到 140 亿，而去年全年仅 100 亿。

他的核心判断是：我们正从"超级早期采用"过渡到真正的爬坡阶段。不再是 Kyle 一个人编程，而是 Kyle 加上一组 agent，共享他的技能、资源和上下文。他认为这不会停止，只会继续增长——无论用什么工具构建，代码最终都会落到 GitHub 上。

对于"$200 订阅如何不膨胀到 $2000"，他给出了两个答案：一是通过 frontier tuning 让模型更深度了解你；二是智能模型路由，根据任务难度自动选择最合适的模型。他坦言，即便知道简单任务用轻量模型就够，大多数人也不会手动切换——这恰恰是工具该解决的问题。

最出圈的细节：Kyle 自己维护着一个 AI 版"Kyle"用于持续自我反馈。每七天，AI 会读取他所有的邮件和 Slack 消息，告诉他哪里表达不够清晰、用了太多类比、以及如何改进。他说："人类更愿意接受来自机器的批评，而不是来自其他人的。这一点在 GitHub 做聊天机器人的时代就已经被验证了。"

> "如果我假设在 token 使用上拥有充分的选择权……真正长期重要的事情，似乎从 ChatGPT 诞生之初就已经存在了：个性化、属于我自己、上下文、fine-tuning……这些想法一直都在，却始终没有一个跨行业的长期愿景去落地它们。"
