### Boris Cherny（Claude Code，Anthropic）

Anthropic Claude Code 工程师 Boris Cherny 发了一条 7000+ 点赞的长推，核心论点是：**自动化在 AI 时代比以前更重要，不是更不重要**。

他的逻辑链：过去顶尖工程师花大量时间自动化自己的工作（vim 宏、lint 规则、e2e 测试）。现在这件事的杠杆被放大了三倍。第一，你加速了自己，也同步加速了你运行的所有 agent。第二，写一条 lint 规则来修复某类 bug，比让 Claude 每次遇到都修一次便宜得多，而且覆盖更完整。第三，自动化降低了 context 门槛，让不熟悉代码库的工程师、甚至非工程师能在第一天就贡献代码——前提是领域知识已经被编码进了 CLAUDE.md、REVIEW.md、skills 和文档里，而不是锁在人的脑子里。

他的结论："每个团队都应该把自己的领域知识转化为基础设施，让 Claude 不需要额外提示就能有效工作。"

### Aaron Levie（Box CEO）

Box CEO Aaron Levie 整理了一场与大企业 IT 领导者晚宴的讨论要点，关于企业 agent 落地的真实状态：

- **变革管理**仍是最大痛点，大多数流程需要同时更新技术、数据和人工流程才能配合 agent 工作
- IT 团队发现，**把技术人员嵌入业务部门**（内部 FDE）可以大幅加速试验，因为让 agent 成功需要大量技术工作
- **软件必须 headless**成为共识：企业不再需要培训员工使用数百个不同的 app，但传统软件供应商在 API 和成本上配合度很低，这是个"大危险信号"
- 开发者和非开发者之间的 **AI 预算差距极大**：开发者可达每月 5000 美元，非开发者远低于此
- **多模型路由系统**越来越常见，企业自己搭建系统把任务路由到不同模型

### Claude Blog：Claude Code 现已支持 Artifacts

Claude Code 新功能：可以把工作进度生成为 **artifact**——一个实时更新的、可分享的可视化页面。支持的场景包括：PR 走查、系统说明文档、数据仪表板、发布 checklist 等，页面会随 session 进展自动更新。

核心特点：
- 基于完整的 session context 构建，包括代码库、已连接的工具以及整个对话内容
- **同一链接实时更新**，团队成员打开页面即可看到最新进展
- 所有 artifact 默认私有，可分享给组织内成员，不可设为公开

典型用例：工程师在站会前开启一次事故调查，Claude Code 生成一个包含时间线、可疑提交和错误率图表的页面，调查期间自动重新发布两次——团队成员不需要等人讲解，直接看同一视图。

目前处于 Beta 阶段，面向 Claude Team 和 Enterprise 用户开放。

### AI & I by Every：一家 15 亿美元 AI 公司的创始人谈第一波 AI 应用之后的下一步

**要点：会议记录从来不是终点，争夺的是 AI 时代的工作界面本身。**

Granola 联合创始人兼 CEO Chris Pedregal，在与 Every CEO Dan Shipper 的对话中，坦诚分享了从 12 人到 60-70 人的成长阵痛，以及他对 AI 应用层竞争的反直觉判断。

**论竞争：** Notion、OpenAI、Zoom 都抄了 Granola 的核心功能，但对增长率几乎没有影响。他的逻辑不是"我们的护城河很深"，而是："**会议记录本身不是终点，大家现在争的东西根本不重要，真正的机会在前面——谁能定义 AI 原生时代的工作界面，谁才赢了。**"Easy come, easy go。

**论产品哲学：** Granola 的产品比喻是"扶手杆"——你永远不会注意到它，直到你快摔倒的那一刻，它必须在那里，而且必须是承重的。为此，他们预先生成了数百万份会前简报，哪怕只有 10% 会被打开，因为那 15 秒的窗口期才是关键时刻。

**论 agent 原生策略：** 他明确表示 Granola 的 API 和 MCP 会在未来几个月大幅提升，目标是让用户"把自己的 agent 带来用 Granola 的 context"，而不是封闭生态。一个典型案例：一位销售用 Claude 读取 Granola 的会议记录，自动生成样式匹配客户网站的微站。这是 Granola 不会自己去做但愿意赋能的场景。

**论 Fable 的影响：** 他坦白，Fable 发布后才第一次认真追踪团队的 token 消耗，因为有工程师一天花了几千美元。"我们竟然不知道自己花了多少——这件事本身说明我们太忙了。"

一句直接引语值得记住：*"Startups are knife fights. And I thought they were just really hard when they weren't working. Turns out they're really hard even when they're working as well."*
