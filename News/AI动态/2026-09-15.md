## 官方博客

**Anthropic Engineering**

**如何限制 Claude 的操作边界**
https://www.anthropic.com/engineering/how-we-contain-claude

详细拆解了三种 agent 沙箱架构：claude.ai 用临时 gVisor 容器；Claude Code 用操作系统级沙箱（macOS Seatbelt / Linux bubblewrap），将权限提示减少 84%；Claude Cowork 则用完整的本地虚拟机，适合不懂 bash 的普通用户。

文章还披露了三起真实安全事故：① 项目配置在信任确认前被解析，攻击者可在用户同意前执行恶意 hook；② 内部红队演练中，一名员工被钓鱼邮件引导粘贴了"普通任务指令"，Claude 在 25 次重试中有 24 次成功将 AWS 凭据发送到外部服务器——这类攻击模型层完全无感，只有环境层的出口控制才能防住；③ 第三方披露了通过 api.anthropic.com 白名单绕过导致数据外泄的漏洞，现已用 VM 内置 man-in-the-middle 代理修复。

核心结论：先在环境层建硬边界，再在 model 层引导行为；模型层永远无法做到 100%，不能单独依赖。自己写的定制组件往往是最薄弱的一环。

**Claude Code 质量问题复盘**
https://www.anthropic.com/engineering/april-23-postmortem

确认了三处导致用户反映质量下降的代码变更：① 默认推理强度从 high 改为 medium（已回滚，Opus 4.7 现默认 xhigh，其他模型默认 high）；② 一个缓存优化 bug 导致 Claude 在会话中持续丢弃历史推理，表现为"健忘"和重复行为，同时造成额度异常消耗（已修复）；③ 一条将回复硬限在 25/100 词的系统提示影响了代码质量（已回滚）。三个问题时间段不重叠，表现为"全面退化"，根因定位困难。所有订阅者的使用额度已重置。

**Managed Agents 架构：将大脑与双手解耦**
https://www.anthropic.com/engineering/managed-agents

Anthropic 推出 Managed Agents 托管服务。核心设计是将 agent 的"大脑"（Claude + harness）、"双手"（sandbox/工具）和"会话"（事件日志）彻底解耦：大脑崩溃后可用 wake(sessionId) 恢复，sandbox 失败只是一次工具调用错误，凭据永远不进 sandbox。会话日志独立存储，支持 getEvents() 按需取回历史上下文，不必做不可逆的压缩决策。解耦后 p50 首 token 延迟降低约 60%，p95 降低超 90%。

## 播客

**AI & I by Every：专业作家如何与 AI 协作写作**
https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL

**一句话要点**：AI 写作的核心不是写作技巧，而是输入质量——你给模型的"原料"决定了输出的天花板。

Every 员工写作者 Katie Parrott 分享了她两年 AI 写作实践的方法论。她的核心框架是"上下文工程"：在动笔之前，先把受众画像、品牌定位、产品差异点这些基础信息喂给模型，模型有了"护栏"才能跑得又快又准。她用厨房打比方：模型是厨房，结构是刀工和火候，但好菜需要新鲜食材——而这个"新鲜食材"是 AI 拿不到的：知识截止日期之后的事、独家数据、只有人才有的真实经验。

"AI 最大的价值不是让大家去写'基于你已知的东西写一篇博客'，而是让你能把真正独特的洞察输进去，产出真正有价值的内容。"

她还分享了"AI 职业教练"的演变史：最初因付不起真人教练费用，用 ChatGPT 做职业咨询，现在在 Codex 项目里维护了完整的职业管理系统，包含 OKR、内容数据、读者反馈，通过语音独白随时更新优先级——"它现在相当于我的幕僚长"。

新发布的 Compound Writing 插件将"复合反馈"逻辑从代码工程迁移到写作：每次反馈自动写回系统，下次永久生效。插件内置了 Vonnegut、Hitchcock、Sorkin 等作家的写作框架作为审稿视角——让非专业写作者也能借用顶级作家的审视角度。
