## PODCASTS

**AI & I by Every｜Why Every Traded Personal Agents for One Company Agent**

**核心观点：** 个人 agent 看起来诱人，但维护成本与安全负担太重；真正沉淀下来的价值会向「一个全公司共用的 agent」集中，个人 agent 则退回到家庭与私人场景。

Every 团队走完了一条完整的弯路：先让人人都配一个个人 agent（早期 OpenClaw 时代），最后又把这些能量收拢成公司共用的一个 agent，甚至把它做成了对外发布的产品 Every Agent。平台负责人 Willie Williams 与 CEO Dan Shipper 复盘了这条路径。

最初 OpenClaw 在公司内扩散靠的不是文档，而是「看见别人怎么用」，面对面演示远比解释有效，大家发现「原来还能这样 prompt」。但很快 Slack 里就一堆 bot 乱跑，安全、配置、运维全成了门槛。团队一度想做一个让非技术同事一键造 Claw 的平台（代号 Plus One），结果失败，因为 OpenClaw 迭代太快、又是彻底 vibe code 出来的产品，很难当作平台底座；到最后所有人的 Claw 基本都死了，Dan 那只叫 R2C2 的 Claw 也在 Mac mini 断电后再没重启过。

他们的教训是：不是每个人都想维护自己的 agent，连爱折腾的人也会在出现更好选项后放弃，而且记住「哪个 agent 管什么」本身就烦。于是一个能力被持续投入、全公司共享、拿出来就能用的 agent 反而更有价值，同事 Austin 的 growth agent 就曾成为整个公司的引力中心。这里有个反复出现的分野：builder 愿意直面复杂度去拧旋钮，operator 只想要「能用就行」。

Willie 说，在他做过的所有岗位里，工程管理和以前最像。manager 的杠杆依然是「能看到多大范围的战场」，而团队杠杆变大后，自己的杠杆也变大，最该花力气的地方是找瓶颈、拆瓶颈。他把 Slack、邮件、会议、客户反馈汇总成一条自建 feed（Tend），让 agent 每五分钟扫一次异常并做智能路由，甚至让 agent 当第一顺位 on-call，「不用再排假期」。

两人都判断未来会分工：职场里是「一个公司（或组织）一个 agent」，因为它能持续学习工作流，每个人用一次就贡献一次；家庭与个人侧则是高度个性化的私人 agent。角色化有真实吸引力，Willie 给自己的 Grok Bot 配了不同的「教练」（游泳教练、心理教练），像人类一样分角色更好理解;但 Dan 认为在工作场景里，只要出现更强的产品，用户会毫不犹豫抛掉那个有感情的小角色。最终形态可能是「影子组织架构」：一个很强的顶层公司 agent，按需分裂出团队级 agent，再延伸为个人的 dot。

> "My take on technology is: you're never wrong. You're just too early usually."
