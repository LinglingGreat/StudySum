## OFFICIAL BLOGS

**Claude Blog — Claude in Chrome 正式全面上线**

Claude in Chrome 现已向所有 Claude 付费计划用户开放，且新增了"自动审批"模式——Claude 可以自主执行判断为安全的浏览器操作，不再每步都等用户确认（可在设置里关闭）。这项能力的核心挑战是 prompt injection 防御：恶意网站可能在页面中藏入指令，试图劫持 agent 行为。Anthropic 的应对方案是三层叠加防护：（1）持续训练 Claude 识别不断增长的攻击样本库；（2）对 tool 返回的 web 内容用 probe 扫描，发现可疑内容时提醒 Claude 谨慎处理；（3）执行前用 safety classifier 校验每个动作是否与原始请求一致，不符合则拦截。最新评测显示：在启用全套防护的条件下，针对 Sonnet 5 和 Opus 5 的攻击成功率为 0%，Fable 5 为 0.3%（已验证均为低危场景）。

**Claude Blog — Cowork 获得内置浏览器**

Claude Cowork 桌面应用新增了内置浏览器。当任务需要访问网页时，浏览器会在侧栏自动打开，Claude 可以导航、阅读、点击和填写表单——无需安装扩展，不共享用户的个人浏览器（标签页、书签、密码均隔离）。用户可以选择将特定网站的登录凭据同步进来（银行、邮件、SSO 默认排除在外）。与 Claude in Chrome 的定位区分：内置浏览器适合把整个 web 任务交给 Claude 异步完成（如收集发票、整理报告），Claude in Chrome 则适合在用户当前打开的页面上协作操作（如更新 CRM、处理收件箱）。目前向 Pro/Max/Team 计划逐步推送。

## PODCASTS

**No Priors — Redefining Chip Architecture with Arm CEO Rene Haas**

**一句话核心：** CPU 从未被取代——AI inference 时代，token 生成之后的"路由和调度"都要靠它。

Rene Haas 从 Nvidia 老兵的视角给出了一个反直觉的判断：ChatGPT 爆发后全行业聚焦于 GPU accelerator，但 CPU 从未消失，它承担着 token 调度和系统编排的不可替代角色。"No computing problem has ever been invented that doesn't utilize the microprocessor. It is the heart of everything."

他对 AI 加速芯片设计的看法同样务实：AI 工具在 verification、validation 和 debug 阶段的价值远大于 RTL 生成——因为设计阶段耗时反而不是最多的，文档和验证才是瓶颈，而 AI 恰好擅长这部分。ARM 内部约 80-90% 的工程师每天使用 AI 工具，"如果把它关掉，就像 1990 年代有了互联网，却被告知每天只能在下午两点到四点之间上网。"

对于芯片设计周期的展望：他认为 5 年内有可能对简单设计实现从想法到 GDS 文件（送交流片的最终文件）的全自动化，但对复杂高性能设计，"press a button and get something 10% faster" 在短期内不现实。

ARM 进入自研芯片领域（与 Meta 合作推出 ARM AGI CPU）的逻辑是：部分客户有能力自己设计芯片，但更多公司想要基于 ARM 的产品却没有设计能力，ARM 填补这个空白。与 Nvidia、Amazon、Google 等现有客户的关系比预期顺畅，因为更多可用软件生态对整个 ecosystem 都有利。
