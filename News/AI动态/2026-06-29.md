**Claude Blog：Claude Code 现已支持 Artifacts**

Claude Code 推出 Artifacts 功能：在一个 coding session 里，可以将工作成果封装为可实时更新、可分享的网页——包括 PR walkthrough、系统架构说明、数据 dashboard、发布检查清单等。每次 session 更新后，所有打开该链接的成员实时看到最新版本，版本历史支持随时回滚。

**核心场景：** 工程师开始事故排查前让 Claude Code 创建一个 Artifact，Claude 将日志、疑似问题提交、错误率图表整合成一页发给整个团队；排查过程中 Artifact 自动更新——站会上大家看的是同一份实时文档，无需再"把 agent 发现了什么讲给大家听"。

**权限控制：** 每个 Artifact 默认仅对作者可见，分享后仅限组织内认证成员访问（不可公开）。管理员可通过 org-level toggle 和 role-based scoping 控制访问权限，合规 API 提供全组织可见性。目前以 beta 版形式向 Claude Team 和 Enterprise 组织开放，支持 CLI 和桌面端，网页可在任意浏览器查看。

## PODCASTS

**Training Data：记忆与持续学习——Engram 联合创始人 Dan Biderman 和 Jessy Lin**

**核心观点：** RAG 解决了"存什么"的问题，但真正的难题是"怎么调用"——而这需要模型把知识内化到权重里。

Engram 是一家专注于 AI 记忆与持续学习的 NeoLab。联合创始人 Dan Biderman（神经科学背景）和 Jessy Lin（计算认知科学背景）在这期播客里深入探讨了一个核心问题：为什么 context engineering 和 RAG 远远不够，以及如何让模型真正"学会"新知识。

**他们的核心论断：** 前沿实验室的 P0 是训练更大更通用的模型，"记忆"和"持续学习"目前只是产品侧的副业。Engram 押注这个方向值得独立攻克——Demis Hassabis 在约一个月前的 Sequoia 活动上也明确表示这个领域需要新的突破。

**RAG 的根本局限：** 外化记忆（RAG、context window）的问题不是存储，而是"知道去哪里找"——模型有时根本不知道该搜索什么。真正的智能需要在你没有明确提问的情况下，主动联想出相关信息，而这种关联只能在权重里发生，不能靠检索实现。

**一个触目惊心的对比：** 一篇维基百科文章的 KV cache 占用约 80GB 显存，而整个 70B Llama 模型的权重只需约 100GB 就能"记住整个互联网"。这种数量级的差距，正是 Engram 想要通过训练压缩来解决的——他们估计对于某些场景，内化训练可实现 100x 的 token 消耗降幅。

**产品路径：** 针对 Notion、Microsoft、Harvey 等有大量工作流数据的企业，训练团队级别的 adapter（LoRA / prefix / sparse architecture 等），让模型从实际文档和交互中持续学习，而不是每次推理都重新"读文件"。他们的愿景是：每个人、每个团队拥有自己的专属模型，就像 Databricks / Oracle 成为数据平面的接口一样，Engram 成为神经记忆层的接口。

> "如果你今天辞职，唯一的目标是让模型更好地服务自己，你能做的空间是非常有限的——不如等下一个版本的模型。我们希望看到一个未来：你投入的时间真的能转化为更好的性能。"
