### Anthropic Engineering：近期 Claude Code 质量问题复盘

https://www.anthropic.com/engineering/april-23-postmortem

Anthropic 发布了关于今年 3-4 月 Claude Code 质量下降的详细事后分析。经调查，问题源于三次独立的代码变更：

1. **推理努力等级降级**（3 月 4 日）：为降低延迟，将 Claude Code 默认推理等级从 high 调整为 medium，导致用户体验到智能下降。4 月 7 日回滚，目前 Opus 4.7 默认使用 xhigh，其他模型使用 high。

2. **缓存优化 bug**（3 月 26 日）：原本设计为空闲超过一小时的会话清除一次旧的 thinking 记录，但 bug 导致每一轮都在清除，使 Claude 变得"健忘"、重复行为增多。4 月 10 日修复。

3. **系统 prompt 改动**（4 月 16 日）：为降低 Claude Opus 4.7 的冗长性，添加了字数限制指令，导致编程质量下滑，4 月 20 日回滚。

Anthropic 指出，三个问题影响的流量切片不同、时间错开，导致整体看起来像是广泛的随机性退化，难以定位。后续将执行更严格的系统 prompt 变更管控、更广泛的 per-model eval 套件，以及更长的灰度周期。作为补偿，已为所有订阅用户重置 usage 限额。

### Claude Blog：Claude Managed Agents 内置记忆功能上线公测

https://claude.com/blog/claude-managed-agents-memory

Claude Managed Agents 的跨会话记忆功能正式进入公测。核心设计：记忆以文件形式存储在 filesystem 上，与 Claude 擅长的 bash 和代码执行能力深度结合，而非独立的向量数据库。支持多 agent 共享同一个记忆 store，并设置不同读写权限（如全局 store 只读，用户级 store 可读写）。所有记忆变更带有详细 audit log，可追溯、可回滚、可在 Claude Console 中查看会话事件。

已有团队验证效果：
- Rakuten 的长时运行 agent 通过记忆学习历史错误，首次处理错误率降低 97%
- Wisedocs 的文档验证流水线通过记忆识别重复问题，速度提升 30%

### AI & I by Every：《解密 Claude Platform 的构建秘密》

https://www.youtube.com/watch?v=lLypHkIVLqc

**核心观点：AI 平台的本质是"让你用最少的工作得到最好的结果"，而非只是提供 API endpoint。**

Anthropic 平台产品负责人 Angela 和工程负责人 Caitlin 分享了构建 Claude Managed Agents 背后的决策逻辑。

最值得关注的几个判断：

**模型与 harness 应该深度耦合，而非通用化。** Angela 认为，曾经"通用 harness + 热插拔模型"的做法在旧时代勉强可行，但现在各家实验室的模型差异化越来越大，真正的 alpha 来自于针对特定模型做 harness 工程优化，而非追求通用性。

**基础设施才是大多数团队真正撞上的墙，而非 prompt 工程。** Caitlin 指出，大多数人以为 harness 工程是难点，但实际上当他们把 agent 推向生产时，才发现服务器持续运行、沙箱崩溃恢复、异步长任务管理才是真正的障碍。

**多 agent 协同正在解锁新的"架构策略"层。** Angela 描述了多种正在被探索的多 agent 架构：执行与建议分离、生成与对抗并行、群体式 bug 搜索等。每种架构适合不同场景，LEGO 式的原语组合正在产出比单一 agent 更有趣的结果。

**agent 的未来形态是"只需告诉我目标和预算"。** Angela 展望未来一年：Claude 会好到能理解自己、自动决定用哪个模型、自动生成合适的 harness，用户只需提供可验证的目标和 token 预算。这并不是遥不可及的愿景，她认为"目标"这一半在一年内就可能实现。

直接引用 Angela："harness 和模型的组合才是真正的 alpha 所在，越来越多团队在往这个方向走。"
