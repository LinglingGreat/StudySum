## 官方博客

### Claude Blog：Claude Managed Agents 新功能 — Dreaming、Outcomes、多 agent 编排

**链接**：https://claude.com/blog/new-in-claude-managed-agents

Anthropic 为 Claude Managed Agents 发布三项重大更新：

**Dreaming（梦境/自我进化）**：以 research preview 形式上线。Dreaming 是一个定期运行的后台进程，会回顾历史 session 和 memory store，提取规律，并让 agent 随时间自动优化。可以完全自动更新 memory，也可以在人工审核后再落库。特别适合长期运行和多 agent 编排场景。

**Outcomes（目标驱动）**：开发者编写成功标准（rubric），agent 据此工作；一个独立的 grader 在自己的 context window 中评估输出，不受 agent 推理过程影响。若不达标，grader 指出问题，agent 重新来过，直到达标。内部测试显示，Outcomes 在最难任务上的成功率提升最多达 10 个百分点，文件生成质量也显著提升（docx +8.4%，pptx +10.1%）。

**多 agent 编排**：当单个 agent 无法胜任复杂任务时，Lead agent 可将任务拆分并委派给拥有独立 model、prompt、工具的 specialist agent 并行执行。所有 agent 共享同一文件系统，事件持久化，Claude Console 提供完整追踪。

**实际落地案例**：
- Harvey（法律 AI）：使用 Dreaming 后，agent 跨 session 记住了文件类型的 workaround 和工具特定模式，任务完成率提升约 6 倍
- Netflix：用多 agent 编排分析数百个构建的日志，并行处理后只汇报跨构建的共性问题
- Spiral by Every：Lead agent 用 Haiku 接单、分发，子 agent 用 Opus 起草。通过 Outcomes 确保每篇草稿符合 Every 的编辑原则和用户语气，才返回给用户
- Wisedocs：文档质量审查速度提升 50%

### The MAD Podcast with Matt Turck

**节目**：The MAD Podcast with Matt Turck
**嘉宾**：Aaron Levie（Box CEO）
**题目**：State of Enterprise AI 2026: Aaron Levie on Tokenmaxxing, Rise of Headless, and AI-Proofing Your Job

**核心洞察**：企业 AI 的真正瓶颈不是技术能力，而是组织扩散——而技术进步本身正在拖慢这一扩散。

Aaron Levie 以罕见的双重视角审视企业 AI 现状：一方面他是硅谷的 AI 重度用户，另一方面他的公司直接服务全球 500 强企业的 CIO。他的核心判断是：**我们现在仍处于 day one**，不是因为技术不行，而是因为每一波技术突破都让企业刚刚建好的架构变得过时，导致没有稳定的落地基础。

关于 token 成本：企业们正经历"不舒服的接受式惊讶" — 他们确实看到了生产力收益，所以还在付账，但规模远超预期。IT 预算（占营收 3%-7%）已无法容纳 AI 支出，必须迁移到各业务线的 OpEx。但业务线没有 FinOps，没有人知道一个 agent 任务会花多少钱。他认为"AI 计算的 ERP"是一个价值数十亿的创业机会。

关于无头软件（Headless）：复杂查询确实应该走 headless/agent 路径，但有 GUI 的场景仍会长期存在。未来企业软件将同时拥有 seat 模式和消耗模式两种定价，在某些业务中消耗模式甚至会超过 seat 模式。

关于就业：他是 Jevons 悖论的坚定信徒。AI 不会消灭岗位，而是让那些原本"买不起专职人员"的公司终于能雇人了。Caterpillar、Eli Lilly 这样的工业巨头，有了 AI 加持后，工程师的产能可以翻 3-10 倍，因此他们会签下更大的项目，需要更多工程师。

最值得关注的新角色：**内部 FDE（Field Deployment Engineer）** — 嵌入业务团队的技术人，负责理解业务工作流并用 agent 重构它。这将是未来数年企业 AI 落地的关键岗位，既不会被 AI 替代，也不是一次性的实施工作。

> "The technology is getting so advanced that it makes obsolete the prior thing that you implemented, which actually means that the rollout takes longer."
